# 使用 RouterOS 进行简单的域名分流

## 原理

主要使用 RouterOS 两个功能：

1. **DNS Static**：解析特定域名，并把解析到的 IP 记入 `/ip/firewall/address-list`。
2. **routing-mark**：按 address-list 标记流量，把指定入口/出口的包转发到旁路由。

第 2 步的 routing table、反环路、FastTrack 见 [1.RouterOS 旁路由实现](<./1.RouterOS 旁路由实现.md>)。本文只补「域名 → IP 列表」，以及把它接到已有的 `to-bypass` 标记上。

需要 **RouterOS 7.17+**（`/ip dns static` 的 `address-list` / `match-subdomain`，以及 `/ip dns forwarders`）。

## 环境

与文档 1 相同：

- 旁路由（软路由）：`192.168.88.6`
- 需要分流的客户端：`192.168.88.15`
- 主路由 LAN：`192.168.88.1`（客户端的默认网关 **和 DNS**）

客户端必须向主路由做 DNS 查询。主路由只有亲眼看到解析过程，才会把 IP 写入 address-list。客户端若用 DoH/DoT，或 DNS 指向 `8.8.8.8` 而不经过主路由，分流不会生效。

## 1. 主路由开启 DNS

```routeros
/ip dns
set allow-remote-requests=yes servers=8.8.8.8,1.1.1.1 address-list-extra-time=24h
```

这里的 `servers` 只服务**未**做 FWD 的普通域名，污染影响相对小。分流域名走下一节的 Forwarder，不要用这组地址。

`address-list-extra-time`：CDN 域名 TTL 往往只有几十秒，列表项会跟着 DNS cache 过期。额外挂 24 小时，避免 IP 刚从列表里掉出去、连接又被送回主路由 WAN。

DHCP 把主路由当成 DNS 发给客户端（MikroTik 默认如此）。若客户端是手写 DNS，改成 `192.168.88.1`，或做下面的劫持。

强制 `192.168.88.15` 的 53 端口回主路由，避免它绕开：

```routeros
/ip firewall nat
add chain=dstnat src-address=192.168.88.15 protocol=udp dst-port=53 \
    action=redirect to-ports=53 comment="dns hijack udp"
add chain=dstnat src-address=192.168.88.15 protocol=tcp dst-port=53 \
    action=redirect to-ports=53 comment="dns hijack tcp"
```

不要劫持旁路由 `192.168.88.6` 自己的 DNS。

## 2. DNS Static 写入 address-list

先建一个 named Forwarder。`type=FWD` 的 `forward-to` 填这个名字，不要直写 IP。一个 Forwarder 可以挂多个上游，查询按 round-robin 轮询。

分流域名**不要**把 `8.8.8.8` / `1.1.1.1` 当上游：国内链路里这两个地址经常被劫持或污染，解析结果是假 IP，写进 `proxy-domains` 之后流量会打到错误目标。改走旁路由上已经「干净」的 DNS（常见是旁路由自己的 dnsmasq / AdGuard Home / Clash，监听 `192.168.88.6:53`）。

```routeros
/ip dns forwarders
add name=split-fwd dns-servers=192.168.88.6
```

主路由查旁路由 DNS 是局域网，会被 `pbr: skip LAN` 放行，不会标进 `to-bypass`。旁路由这份 DNS 必须做**真实解析**（不要 fake-ip）：fake-ip 会把 `198.18.0.0/16` 写进 address-list，后面的 PBR 就乱了。

`type=FWD`：该域名（及子域）交给 `split-fwd` 解析，解析结果进入 `proxy-domains`。IP 本身不改写，客户端拿到的仍是真实地址。

```routeros
/ip dns static
add name=github.com type=FWD forward-to=split-fwd match-subdomain=yes \
    address-list=proxy-domains comment="split"
add name=githubusercontent.com type=FWD forward-to=split-fwd match-subdomain=yes \
    address-list=proxy-domains comment="split"
```

按需继续 `add name=...`。`match-subdomain=yes` 会把 `xxx.github.com` 一并纳入。

一条 regex 也可以，但误伤面大，只建议非常明确的后缀：

```routeros
/ip dns static
add regexp=".*\\.youtube\\.com" type=FWD forward-to=split-fwd \
    address-list=proxy-domains comment="split regex"
```

在客户端 `192.168.88.15` 上，用主路由当 DNS 查一次目标域名（不要直接打开浏览器，浏览器可能走 DoH，主路由看不到）：

```sh
nslookup github.com 192.168.88.1
```

应返回真实 A 记录，且 Server 是 `192.168.88.1`。若仍是运营商劫持页、明显不相关的 IP，说明 `split-fwd` 没有问到旁路由上的干净 DNS。

然后在主路由上核对 cache 和 address-list：

```routeros
/ip dns cache print where name~"github"
/ip firewall address-list print where list=proxy-domains
```

cache 里有对应 A 记录、`proxy-domains` 里出现同一个 IP，这一步才算通。列表为空通常是：查询没经过主路由，或还没有任何查询。

## 3. 接到旁路由的 routing-mark

[文档 1](<./1.RouterOS 旁路由实现.md>) 里已经建好 table `to-bypass`、下一跳旁路由，以及 `pbr-clients`。整机旁路由的 mangle 不限制目的地址。改成只走分流域名：

```routeros
/ip firewall mangle
set [find comment="pbr: mark clients"] dst-address-list=proxy-domains
```

流量路径：

1. 客户端查询 `github.com` → 主路由 FWD 到 `split-fwd`（旁路由上的干净 DNS）→ IP 进入 `proxy-domains`。
2. 客户端连接该 IP → prerouting 命中 mangle → `routing-mark=to-bypass`。
3. 查 `to-bypass` 表，下一跳旁路由。

未在 DNS Static 里的域名不会进列表，仍走主路由默认 WAN。

# Mac Mini + Clash 做旁路由

主路由策略路由见 [1.RouterOS 旁路由实现](<./1.RouterOS 旁路由实现.md>)。本文只写旁路由这一侧：Mac Mini 跑 Clash（mihomo / Clash Meta），用 TUN 接管被主路由丢过来的包。

## 环境

与文档 1 相同。Mac Mini 就是那台旁路由。

| 角色 | 地址 |
| --- | --- |
| 主路由 | `192.168.88.1` |
| Mac Mini（旁路由） | `192.168.88.6` |
| 客户端 | `192.168.88.15` |

Mac Mini 默认网关指向主路由，**不要**把自己当客户端的网关。

## 1. 固定 LAN 地址

有线接入主路由 LAN。系统设置里把网卡改成手动：

- IP：`192.168.88.6`
- 掩码：`255.255.255.0`
- 路由器：`192.168.88.1`
- DNS：`192.168.88.1`（本机解析走主路由即可；给别人用的干净 DNS 由 Clash 提供）

## 2. 别让它睡着

旁路由要一直转发。系统设置 → 能量：接电源时防止自动休眠，并允许网络唤醒。

## 3. 打开 IP 转发

macOS 默认不转发。Clash 的「允许局域网」**不会**帮你开这个开关。

```sh
sudo sysctl -w net.inet.ip.forwarding=1
```

重启后失效的话写入：

```sh
echo 'net.inet.ip.forwarding=1' | sudo tee -a /etc/sysctl.conf
```

确认：

```sh
sysctl net.inet.ip.forwarding
# net.inet.ip.forwarding: 1
```

## 4. Clash TUN

用 mihomo / Clash Verge / FlClash 一类带 Meta 内核的客户端。系统代理不够，必须 **TUN**：主路由送来的是普通 IP 包，不是 HTTP/SOCKS。

关键项：

- 开启 TUN
- `allow-lan: true`
- **不要** `strict-route`：开了之后局域网（含主路由）可能访问不到这台 Mac
- **不要 fake-ip**：文档 2 要把真实 IP 写入 `proxy-domains`。用 `redir-host`

```yaml
allow-lan: true
bind-address: "*"

tun:
  enable: true
  stack: mixed
  auto-route: true
  auto-detect-interface: true
  strict-route: false
  dns-hijack:
    - any:53
  route-exclude-address:
    - 192.168.88.0/24

dns:
  enable: true
  listen: 0.0.0.0:53
  ipv6: false
  enhanced-mode: redir-host
  nameserver:
    - https://dns.google/dns-query
    - https://1.1.1.1/dns-query
```

`auto-route` 会把默认路由引进 TUN，避免包从 Mac 原样打回主路由形成环路。`route-exclude-address` 把 LAN 留在物理网卡上。

规则里局域网走 DIRECT，例如 `IP-CIDR,192.168.88.0/24,DIRECT,no-resolve`。

TUN 需要 root / 安装系统服务，按所用客户端的提示装一次。

## 5. 给主路由用的 DNS

文档 2 的 `split-fwd` 指到 `192.168.88.6`。Clash 必须在 **53** 端口做真实解析（上一节 `dns.listen`）。macOS 绑 53 通常也要服务模式。

不要劫持主路由自己的查询之外的东西；主路由不要 dstnat 旁路由的 53。

## 验证

1. Mac 上 `sysctl net.inet.ip.forwarding` 为 `1`，Clash TUN 已亮。
2. 本机访问外网正常，且能 ping `192.168.88.1`。
3. 主路由按文档 1 把客户端标进 `to-bypass` 后，Clash 连接列表里应出现对应流量（源地址多半是主路由 `192.168.88.1`，因为文档 1 做了 SNAT）。
4. 文档 2：在客户端 `nslookup github.com 192.168.88.1`，应拿到真实 A 记录，不是 `198.18.0.0/16`。

## 注意

- 只用 Wi-Fi 时关掉「专用 Wi-Fi 地址」，地址漂了主路由下一跳就无效。有线更稳。
- `auto-redirect` 是 Linux 的，macOS 上不要开。
- 系统防火墙若拦了转发，给 Clash 放行，或先关防火墙试。
- Mac 自己的出站也被 TUN 接管是正常的；节点 IP 靠 `auto-detect-interface` 走物理网卡，避免套娃。
